What I own

Atlassian build-out on Government Cloud

I stood up Jira, Jira Service Management, and Confluence on Atlassian Government Cloud (FedRAMP Moderate) and moved the company onto it. About 20 teams so far, most coming off Linear and Notion. Our tenant runs without marketplace apps or AI features, so everything is native config, Automation, and the REST API. The pieces I'm proudest of:

  • Change request process. One path for every system change at the company. Four change types (Standard, Normal Minor, Normal Major, Emergency), a director review gate and a GRC review gate, the who/what/why and risk on every request, a test plan and change window, and a change calendar dashboard. Security runs a copy of the same process.
  • Application review and onboarding. App access and app change request forms with a section per app, so the requester only sees the questions for what they picked. Requests route to GRC and then Security depending on how risky the app is. A one-click onboarding automation opens the security hardening task and drops a 12-step checklist into the ticket.
  • Other teams' processes. Intake and workflows for Security, GRC, Finance, Legal, Infrastructure, People Ops, Sales, Business Ops, and Product & Engineering, plus an international travel flow for the security office with a work-abroad gate. I wrote a buildout script that turns a manifest into a fully configured project, so a new team takes hours, not weeks.

RBAC process and policy

I proposed the access model we run on now. Access comes from Okta groups and roles tied to your team and job, not one-off grants. Changes go through a request and approval, including a change request for creating or changing security groups and distribution lists.

GitHub identity and access

SSO and SCIM from Okta into GitHub Enterprise Server, with Okta groups pushed as GitHub teams. Self-service access requests for the restricted org and the SME groups, GitHub-specific questions on the app request forms, and the how-to docs for all of it.

Also built in Jira: approval reminders that escalate and then cancel stale requests, assignee escalation, after-hours notices, approvers and devices auto-filled from Assets, a USB drive request with a security approval gate, a weekly and monthly metrics post in Slack for leadership, dashboards and SLAs, and a lot of cleanup on screens, workflows, and permission schemes.
Also in Okta: Navan SSO and SCIM, managed device required on every CMMC app, an inactive-account suspension flow, offboarding cleanup flows, and the passwordless rollout plan.

Automated compliance evidence

Auditors ask for the same Jira records every cycle: change requests, security incidents, removable-media requests. Scheduled Okta Workflows now pull them, turn each ticket into a readable CSV row (description, every comment, full status history as the approval trail), attach it to the matching evidence record in our GRC platform, and set the next due date. Monthly for changes and incidents, quarterly for media. Every run checks its own work: it confirms it can see each Jira space, compares the ticket count to the rows uploaded, and posts the result or the failure to Slack. That replaced a manual export, clean up, and attach job.
